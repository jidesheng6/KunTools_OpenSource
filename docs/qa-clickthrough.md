# 手工点测脚本（Clickthrough）

给**真人**用的手工回归脚本：自动化（`FeatureSmoke` / `UiSnapshot`）证明了「47 页能创建、布局不溢出」，但证明不了「点下去之后发生了什么」。本脚本只覆盖自动化死角：对话框取消、拖放拒收、体积极大/极小的边界、源=目标的拦截、破坏性输入、单实例。

- 主线（标 ★ 的 17 段）约 **36 分钟**跑完一遍（熟练后 30 分内）；全量 47 页约 **79 分钟**。这两组数字是估计值，未经真人计时验证（见 §8）。
- 判定标准统一三条：**状态行文字与本文写的一致**、**产出的文件真的在磁盘上**、**没有任何英文异常直贴界面**。任一条不符即记为缺陷，记下页面、操作、期望、实际、截图。
- 每段的「失败即记录」= **看到该现象就当场停下来记**（页面 / 点过哪些按钮 / 以为会看到什么 / 实际看到什么 / 截图 + 系统时间），不是「感觉不太对」；照该行描述的现象原样对照即可，不必自己判断严重性，严重性由分诊的人定。

## 0. 前提（不满足就先补，别硬测）

| 项 | 要求 | 不满足时的后果 |
| --- | --- | --- |
| ACE 引擎 | Microsoft ACE OLEDB **12.0**，位数与进程一致（当前进程 `net8.0-windows`，x64 装 x64 版） | 考评类（`exam.*`）打不开 `.mdb`，会报「未安装 ACE」类错误 |
| Office | 本机装有 Microsoft Word（只用于 `word.pdf` 勾「使用本机Office转换」那一条） | 该条与 `useLocalOffice` 相关分支无法验证 |
| Aspose 授权 | 已放授权文件；未授权时 `pdf.merge` 等会撞 **4 元素试用水印/限制** | 只能按「2 + 2」测（每次合并 ≤4 个元素），结论不代表生产 |
| 扫描仪 | 有真机才能测 `twain.debug` 的正常路径 | 无设备时**应当**看到降级文案——这本身也是一条必测项（见该段） |
| 素材 | 见每段「素材」，全部取自仓库 `testdata\`；考评库用 `tools\ExamFixture` 现场生成 | — |

启动方式：`dotnet run --project src\DocumentTools.App`（或直接跑 `bin\Debug\net8.0-windows\DocumentTools.exe`）。

## 1. 壳层（3 段，约 4 分钟）

### ★ home · 首页　〔1 分〕
- **进入路径**：启动后默认落点即首页（左侧导航「首页」）。
- **操作步骤**：看首屏 → 在搜索框里输入 `pdf` → 清空搜索 → 点任意一张功能卡。
- **预期可见结果**：首屏列出全部分组的功能卡；输入 `pdf` 后只剩 PDF 相关（`PDF 转 WORD`、`合并 PDF`…）；清空后恢复；点卡片跳到对应功能页，左侧导航高亮同步。若功能模块未注册，卡片区显示「还没有可以进入的功能：功能模块未注册，或已在「系统设置」里被隐藏。」
- **失败即记录**：搜索后卡片区空白但左侧导航仍有分组（过滤只作用于卡片、未作用于分组时会这样）。

### about · 关于软件　〔1 分〕
- **进入路径**：左侧导航「关于」（或「关于软件」）。
- **操作步骤**：读版本号与许可信息 → 点「刷新许可状态」→ 点「打开 Hook 日志」。
- **预期可见结果**：版本号与 `DocumentTools.App.csproj` 的 `Version` 一致；「刷新许可状态」后状态行/文本给出当前许可结论（不是英文异常）；「打开 Hook 日志」用系统默认程序打开日志文件或提示路径不存在。
- **失败即记录**：许可状态刷新后界面文字仍是上次的旧值（无变化也没提示）。

### ★ 单实例（程序级，不是某一页）　〔1 分〕
- **进入路径**：不进入页面，验证进程行为（`src\DocumentTools.App\Program.cs` 用 `Local\DocumentTools.SingleInstance` 互斥量）。
- **操作步骤**：窗口已开着时，**再双击一次** exe（或再跑一次 `dotnet run`）。
- **预期可见结果**：**不开第二个窗口**；已存在的窗口被唤起并置于前台（`ActivateExistingInstance()`）。
- **失败即记录**：出现第二个主窗口，或第二个进程立刻退出但第一个窗口没被激活（用户以为「点了没反应」）。

## 2. 转换（26 页，主线 8 段约 16 分钟 / 全量约 34 分钟）

本组 26 页共用同一个视图（列表 + 选项 + 底部操作条），所以下面只写**每页的差异点**；共同操作序列是：
**① 点「选择文件」加文件（或把文件拖进列表）→ ② 勾/填「选项」区的参数 → ③ 点右下「开始处理」。**
共同预期：处理中状态行显示蓝色「正在处理第 N 个文件 / 共 M 个：文件名」，结束转绿「处理完毕，成功 N 个文件。」；勾了「保存到源目录」时处理中会多一句「（保存到本文件所在目录：D:\…）」，且**不弹目录选择框**；成功后（若「系统设置」里开着 `ShowOpenTargetDialog`）弹「处理完毕，是否需要打开转换后目录？」。

### ★ 通用契约三条（在任意一页上验证即可，建议用 `word.pdf`）　〔3 分〕
- **进入路径**：左侧「Word」→「WORD 转 PDF」。
- **操作步骤**：① 直接点「开始处理」（列表空）② 点「选择文件」后**在对话框里点取消** ③ 加 2 个文件后再点「开始处理」，在目录选择框点**取消**。
- **预期可见结果**：① 状态行红字「请先点「选择文件」把要处理的文件加进列表。」，**不弹**目录选择框 ② 列表不变、无任何提示 ③ 状态行「已取消，没有处理任何文件。」，无产出。
- **失败即记录**：空列表也弹了目录框；取消后状态行残留上一轮的成功文案。

### ★ 拖放与拒收（任意一页，建议 `pdf.merge`）　〔2 分〕
- **进入路径**：左侧「PDF」→「合并 PDF」。
- **操作步骤**：从资源管理器拖 1 个 `.pdf` + 1 个 `.txt` 进列表 → 再把 1 个 `.docx` 拖进去。
- **预期可见结果**：第一次只收 `.pdf`，状态行红字「已忽略 1 个不支持的文件。」；第二次全是非法文件 → 列表不变、同样提示「已忽略 1 个不支持的文件。」
- **失败即记录**：非法文件被收进列表（后续处理时才失败）；或拒收后**没有任何文字**，用户以为拖拽坏了。

### word.pdf · WORD 转 PDF　〔2 分〕★
- **进入路径**：「Word」→「WORD 转 PDF」；素材 `testdata\word\sample.docx`。
- **操作步骤**：加 `sample.docx` → 勾「使用本机Office转换」+「嵌入字体」→「开始处理」→ 选输出目录；然后**取消勾选**本机 Office 再跑一次。
- **预期可见结果**：两次都产出 `.pdf`；本机 Office 那条走 Word 进程（任务管理器能看到 `WINWORD.EXE` 一闪），另一条走 Aspose，视觉结果一致；状态行只在结束时给一句汇总。
- **失败即记录**：勾了本机 Office 却仍走 Aspose（无 Word 进程）、或反之——参数没进 Core。

### word.merge · 合并 WORD　〔1.5 分〕★
- **进入路径**：「Word」→「合并 WORD」；素材 `testdata\word\merge_a.docx` + `merge_b.docx`。
- **操作步骤**：两个文件按 A→B 顺序加入（用右侧「上移/下移」调序）→「开始处理」→ **在保存对话框里改名为 `合并测试.docx`**。
- **预期可见结果**：弹出**保存文件**对话框（默认名「合并.docx」），选定的文件名被真正使用；状态行「正在合并 2 个文件…」→ 绿色汇总；产物页序与列表顺序一致。
- **失败即记录**：产物落在临时目录而不是你选的位置；取消保存对话框后状态行没写「已取消，没有处理任何文件。」。

### pdf.merge · 合并 PDF　〔1.5 分〕★
- **进入路径**：「PDF」→「合并 PDF」；素材 `testdata\pdf\merge_a.pdf` + `merge_b.pdf`（未授权时一次最多 2+2）。
- **操作步骤**：同上，保存对话框默认名「合并.pdf」→ 合并 → 打开产物核对页序。
- **预期可见结果**：产物页数 = 两文件页数之和，页序 = 列表顺序；少于 5 个元素时无试用横幅。
- **失败即记录**：未授权却在 5 个元素以上"成功"（说明授权检测失效）；或页序与列表顺序不一致。

### word.split / pdf.split / ppt.split · 拆分（3 页）　〔各 1 分〕
- **进入路径**：「Word/PDF/PPT」分组 → 对应「拆分 …」；素材 `testdata\word\sample.docx`、`testdata\pdf\sample.pdf`。
- **操作步骤**：加 1 个文件 → 拆分方式选「每页拆分」→ 跑一次；再改成「按页数 / 每份页数 2」跑一次；`pdf.split` 额外试「按页码范围 1-2」与「删除起始页/结束页」。
- **预期可见结果**：产物按页/按份落盘（`xxx_第1页…`）；`pdf.split` 支持「按书签拆分」勾选；`word.split` **没有**「按书签」项（`FeatureOptionSchemas.SplitSections(includeBookmark: false)`），`ppt.split` 有「幻灯片尺寸设置」分区。
- **失败即记录**：选了「按页码范围」但页数参数仍生效（参数互斥失效）；PPT 页出现 legacy 的 `RightFull` 备注档（已按真实能力删掉）。

### ★ pdf.compress · 压缩 PDF　〔2 分〕
- **进入路径**：「PDF」→「压缩 PDF」；素材 `testdata\pdf\sample.pdf`，另备一个**已经压过的小 pdf**。
- **操作步骤**：加 `sample.pdf` →「开始处理」，记下体积；再加那个极小 pdf，勾「跳过图片压缩」跑一次。
- **预期可见结果**：`sample.pdf` 体积变小；极小文件那条状态行写「压缩完成 1 个文件。其中 1 个文件无可压缩空间，已保留原始内容（xxx.pdf）。」——**产物内容原样保留、不被写坏**。
- **失败即记录**：压后反而更大且没提示；或「保留原始内容」后文件打不开。

### ★ image.compress · 压缩图片　〔2.5 分〕
- **进入路径**：「图片」→「压缩图片」；素材 `testdata\image\sample.png`、`testdata\image\tifgif_src.png`。
- **操作步骤**：加 `sample.png` → 输出格式选 **TIF** → 跑；再选 **GIF** → 跑；再选 JPG、把「图像质量」改 30 → 跑；最后勾「沿用源文件后缀名」跑一次。
- **预期可见结果**：选项区第一行有灰字提示「TIF 适合扫描件/二值文档；彩色照片请选 JPEG。」；TIF/GIF 都能产出**能打开**的文件（GIF 是本实现补的编码器）；质量 30 明显糊、体积明显小；勾「沿用源文件后缀名」后产物是 `.png` 而非 `.jpg`。
- **失败即记录**：GIF/TIF 产出 0 字节或打不开（编码器边界）；「沿用源文件后缀名」无效。

### image.pdf · 图片转 PDF　〔1.5 分〕★
- **进入路径**：「图片」→「图片转 PDF」；素材 `testdata\image\sample.png` + `testdata\image\sample.jpg`（放在**不同目录**再试一次）。
- **操作步骤**：两个图加入 → 不勾「每张图单独PDF」→ 跑；再勾上 → 跑。
- **预期可见结果**：不勾时把 N 张合成 **1 个** PDF，跨目录时会提示「合并结果只能保存到一个目录，但所选文件来自 2 个不同目录；请选择输出目录。」再弹框；勾上时每张图各出一个 PDF。
- **失败即记录**：跨目录合并时**没有**那句提示、直接把产物写进第一个文件的目录（旧缺陷 A1 回归）。

### webp.image / image.ico · WEBP 转图片 / 图片转 ICO　〔各 1 分〕
- **进入路径**：「图片」→ 对应项；素材 `testdata\image\sample.webp`（没有就用任意 webp）、`testdata\image\bmp_src.png`。
- **操作步骤**：`webp.image` 分别输出 PNG / JPG / BMP / GIF；`image.ico` 选「ICO 256」跑一次，再勾「同时输出多尺寸(16/32/64/128/256)」跑一次。
- **预期可见结果**：GIF 能正常显示（不是全黑/单帧损坏）；ICO 多尺寸模式产出 5 个尺寸或 1 个含 5 帧的 ico，且能被 Windows 当作图标加载。
- **失败即记录**：ICO 在资源管理器里显示为白框（帧数据写坏）。

### 其余转换页（word.excel、excel.word、excel.pdf、excel.replace→见 §4、pdf.word、pdf.excel、pdf.ppt、ppt.pdf、word.image、word.epub、epub.word、epub.pdf、html.pdf、pdf.compliance、pdf.watermark.add、pdf.watermark.remove）　〔每页 0.5–1 分，共约 11 分〕
- **进入路径**：左侧对应分组 → 页面标题。
- **操作步骤**：每页只做「加 1 个素材 → 保留默认参数 → 跑 → 打开产物」；有特色的再补一步：`word.image` 切「图片格式 .jpg + DPI 300 + 灰度」；`pdf.watermark.add` 填「水印文字=测试」并把「不透明度0-1」改 0.3；`pdf.watermark.remove` 用刚加了水印的 PDF；`html.pdf` 若报找不到 Chrome，把「Chrome路径」指到本机 `chrome.exe` 再跑；`pdf.compliance` 选「PDF/A-1b」。
- **预期可见结果**：每页都产出文件且能打开；水印可见、移除后看不见；`html.pdf` 缺 Chrome 时**中文**说明缺什么、去哪填。
- **失败即记录**：任何一页把 Aspose 英文异常直贴到状态行（例如 `Evaluation only…`、`Cannot find file`）。

## 3. 标识与条码（2 页，约 5 分钟）

### code.barcode · 简易二维码　〔3 分〕★
- **进入路径**：「工具」→「简易二维码」；素材：任意非条码图片（如 `testdata\image\sample.jpg`）。
- **操作步骤**：内容框输入 `https://example.com` →「生成预览」→ 换「类型=Code128」再生成 → 填多行内容点「批量生成」→「保存 PNG」→ 再点「选择图片…」选 `sample.jpg` →「识别条码」。
- **预期可见结果**：预览区出现条码图（未生成前是灰底提示语，不是空白）；批量模式按行出多张；保存后文件存在；识别非条码图时状态行是**中文三句式**：「识别条码失败：这张图读不出来（可能不是图片、扩展名与内容不符、或文件正被其他程序占用）。请换一张 PNG/JPG 后重试，或先用画图打开确认能正常显示。」——**鼠标悬停在识别结果框上有「技术详情：」+ 英文原文**。
- **失败即记录**：界面上直接出现 `Image loading failed.` 之类英文；或 ToolTip 里没有原文（排障失去线索）。

### code.datamatrix · 特殊二维码校验　〔2 分〕
- **进入路径**：「工具」→「特殊二维码校验」；素材：含 DataMatrix 的 docx/pdf（可用 `testdata\exam\person_template.docx`，或自造）。
- **操作步骤**：「选择文件」加文件 →「开始校验」→ 展开结果树 → 右键树节点试「展开本节点全部内容 / 折叠全部节点 / 打开文件 / 复制节点文本」→ 换一个**不含** DataMatrix 的 pdf 再校验。
- **预期可见结果**：树按「文件 → 页 → 分类」展开；含码的页节点绿色、命中值红色；不含码的文件在树上明确写「（未识别到 DataMatrix）」；空列表时结果区是灰底提示「还没有校验结果：选择 Word/PDF 后点「开始校验」，结果按「文件 → 页 → 分类」展开。」；未选中节点时菜单项置灰。
- **失败即记录**：右键菜单项永远可点（禁用态失效）→ 点了「打开文件」没反应且无解释。

## 4. 替换（2 页，约 5 分钟）

### word.replace · WORD 内容批量替换　〔3 分〕★
- **进入路径**：「Word」→「WORD 内容批量替换」；素材 `testdata\word\sample.docx`（先复制一份，改坏可还原）。
- **操作步骤**：「选择文件」加文件 → 在「查找内容」第 1 行填一个文中**确实存在**的词、第 2 行填一个不存在的词 →「替换内容」对应两行分别填新词 → 点「添加查找项」加第 3 组 → 点第 2 组的「移除」→「开始处理」→ 打开产物核对。
- **预期可见结果**：「查找内容」「替换内容」是**两张独立卡片**且逐行对齐（第 N 行配第 N 行）；只剩 1 组时点「移除」给出红字提示而不是把界面清空；产物里只替换了存在的那组；状态行按「处理完毕，成功 N 个」汇总。
- **失败即记录**：删掉中间组后剩余行的配对**错位**（第 1 行的查找配上第 2 行的替换）。

### excel.replace · EXCEL 内容批量替换　〔2 分〕
- **进入路径**：「Excel」→「EXCEL 内容批量替换」；素材 `testdata\excel\sample.xlsx`（无则自造）。
- **操作步骤**：加文件 → 一组查找/替换 →「开始处理」；再填「清空起始行=2、清空结束行=3」勾「删除行（否则清空）」跑一次。
- **预期可见结果**：第一轮只换文本；第二轮指定行被删（不是清空）；选项区有「EXCEL 清空行数据」分区。
- **失败即记录**：行被清空但没删除（勾选未生效）；或删错了行（行号按 1 起算的语义不一致）。

## 5. 工具（5 页，约 9 分钟）

### idcard.check · 身份证校验　〔1.5 分〕
- **进入路径**：「工具」→「身份证校验」。
- **操作步骤**：粘贴一个**校验码正确**的 18 位号 →「校验」；再改最后一位数字 →「校验」；再输入 17 位短号；再输入含字母的号；点「复制结果」。
- **预期可见结果**：合法时出生日期/性别/顺序码/校验码四行齐全且为绿色，校验码行显示「X（末位应为 X）」；改一位后校验码行转红并给出**应为值**；短号/非法字符给红字中文原因（不是「无效」两个字了事）。「复制结果」把四行一起复制。

## 10. 自动化死角（机器测不到，必须人工点）

`tools\QaFunction` 已经能在真实 `Window` 里点控件、拖放、量行高（见 `docs\qa-report-function.md` §15），但下面几处它够不到、或者够到也不算数，**发版前请照这份清单人工确认**：

| 死角 | 为什么机器测不出 | 人工怎么点 |
| --- | --- | --- |
| Wpf.Ui 主题资源与 `FluentWindow` 模板 | 裸 `Application` 起不来主题，`MainWindow` 模板不实现，`ActualHeight` 全是 `0.0`；只有 `new DocumentTools.App.App` + `InitializeComponent()` 再 `Show()` 才有真实布局 | 起真机，肉眼确认分组头/功能项行高、悬停与选中态、分组折叠展开动画 |
| 拖放的**真实**鼠标轨迹 | 断言只能反射构造 `DragEventArgs` 塞 `DataFormats.FileDrop`，没有 OLE 拖放协商、没有拖影与 `DragOver` 的实时光标反馈 | 从资源管理器真拖一个文件进来；再拖一个非法类型（`.txt`）确认被拒且有中文提示 |
| 控件级键盘与输入法行为 | `TextBox.PlaceholderText` 是 Wpf.Ui 扩展属性，裸 WPF `TextBox` 没有，只能反射读；Tab 焦点链、IME 组合、右键菜单、复制粘贴得真键盘验 | 在只读路径框上按 Tab 聚焦、`Ctrl+C` 复制、开右键菜单；用中文输入法各试一遍 |
| **键盘锁（system.tools「键盘工具」卡）** | 锁键盘装的是全局低级键盘钩子，自动化在无人值守环境里点下去会把自己锁死、后续脚本全部失联，所以机器测试**故意不点** | **必须真机**：进「系统」→「系统工具」→ 点「锁定键盘」→ 状态行变红「已锁定」，此时**任意按键无反应**（试字母、方向键、`Alt+Tab`）→ 用鼠标点「解锁键盘」→ 状态行转绿、按键恢复。三种失败要分别记：① 按键仍生效（钩子没装上）② 锁了之后鼠标也点不动解锁按钮（钩子拦过头）③ 切到别的程序后仍被拦（全局钩子没随失焦撤销）。**测完确认已解锁再离开页面** |
| 系统级对话框 | `IDialogService` 在 harness 里被脚本化实现替换，真实的文件/文件夹选择器、保存对话框、确认弹窗都没走 | 每页点一次「选择…」「保存」，确认默认目录、过滤器、取消后的行为 |
| 托盘 / 单实例 / 提权 / DPI | 跨进程、跨会话，harness 在单进程里跑 | 双开程序验单实例；100% 与 150% 缩放各看一遍；非管理员启动看提示文案 |
| Twain / 网卡 / 注册表等系统写入 | 本机无扫描仪，写操作会污染真实环境（`docs\qa-report-function.md` §11.5 已列「未验证」清单） | 在隔离机按 §11.5 表格逐项点，点完按该表恢复命令还原 |
